# Network Inspectors Tutorial

This tutorial creates one Torch LAN model for `angle` and one for `ddm`, then loads both in the Network Inspectors UI.

The inspector currently supports Torch models only. The required Torch state dict
(`.pt`) and network configuration pickle (`.pickle`) are generated by
LANfactory's [`torchtrain` CLI](../README.md#command-line-interface) when it
trains a LAN model. The UI loads those two artifacts to reconstruct the trained
predictor; JAX `*_train_state.jax` files are not supported by this interface.

## Install

From the LANfactory repository root:

```bash
uv sync --extra ui
```

## Generate Training Data

Use the [`generate` CLI](https://github.com/lnccbrown/ssm-simulators#training-data-cli) from
`ssm-simulators` to create LAN training-data pickle files. Create
`angle_data.yaml`:

```yaml
MODEL: "angle"
GENERATOR_APPROACH: "lan"
PIPELINE:
  N_PARAMETER_SETS: 10
  N_SUBRUNS: 1
  N_CPUS: 1
SIMULATOR:
  N_SAMPLES: 1000
  DELTA_T: 0.001
TRAINING:
  N_SAMPLES_PER_PARAM: 200
ESTIMATOR:
  TYPE: "kde"
```

Create `ddm_data.yaml` with the same contents, changing only:

```yaml
MODEL: "ddm"
```

Generate two data files for each model so the default training/validation split
has at least one file in each set:

```bash
uv run generate \
  --config-path angle_data.yaml \
  --output data/inspector_training \
  --n-files 2 \
  --log-level INFO

uv run generate \
  --config-path ddm_data.yaml \
  --output data/inspector_training \
  --n-files 2 \
  --log-level INFO
```

The CLI creates its standard nested training-data layout beneath the output
directory:

```text
data/inspector_training/
└── data/training_data/lan/
  ├── training_data_n_samples_1000_dt_0.001/angle/
  └── training_data_n_samples_1000_dt_0.001/ddm/
```

## Train with the `torchtrain` CLI

Use LANfactory's [`torchtrain` command](../README.md#command-line-interface) to
train both models. The CLI reads a YAML training configuration, loads the
generated pickle data, and writes the Torch state dict and network configuration
that the Network Inspectors UI consumes.

## Create Training Configs

Create `config_angle.yaml`:

```yaml
NETWORK_TYPE: "lan"
CPU_BATCH_SIZE: 1000
GPU_BATCH_SIZE: 2000
GENERATOR_APPROACH: "lan"
OPTIMIZER_: "adam"
N_EPOCHS: 2
MODEL: "angle"
TRAINING_DATA_FOLDER: "data/inspector_training/data/training_data/lan/training_data_n_samples_1000_dt_0.001/angle"
SHUFFLE: true
LAYER_SIZES: [[100, 100, 100, 1]]
ACTIVATIONS: [["tanh", "tanh", "tanh"]]
WEIGHT_DECAY: 0.0
TRAIN_VAL_SPLIT: 0.8
N_TRAINING_FILES: 10000
LABELS_LOWER_BOUND: np.log(1e-7)
LEARNING_RATE: 0.001
LR_SCHEDULER: "reduce_on_plateau"
LR_SCHEDULER_PARAMS:
  factor: 0.1
  patience: 2
  threshold: 0.001
  min_lr: 0.00000001
  verbose: true
```

Create `config_ddm.yaml` with the same contents, changing `MODEL` and
`TRAINING_DATA_FOLDER` to:

```yaml
MODEL: "ddm"
TRAINING_DATA_FOLDER: "data/inspector_training/data/training_data/lan/training_data_n_samples_1000_dt_0.001/ddm"
```

The `TRAINING_DATA_FOLDER` entry is required by the training configuration
parser. The `--training-data-folder` command-line argument should point to the
same directory and is the path used for loading the data during training.

## Train Both Torch Models

Train `angle`:

```bash
uv run torchtrain \
  --config-path config_angle.yaml \
  --training-data-folder data/inspector_training/data/training_data/lan/training_data_n_samples_1000_dt_0.001/angle \
  --networks-path-base data/torch_models \
  --network-id 0 \
  --dl-workers 1 \
  --log-level INFO
```

Train `ddm`:

```bash
uv run torchtrain \
  --config-path config_ddm.yaml \
  --training-data-folder data/inspector_training/data/training_data/lan/training_data_n_samples_1000_dt_0.001/ddm \
  --networks-path-base data/torch_models \
  --network-id 0 \
  --dl-workers 1 \
  --log-level INFO
```

After training, verify that both models have a state dict and network config:

```bash
tree data/torch_models
```

The exact layout may include a network-type directory, for example:

```text
data/torch_models/
├── angle/
│   ├── ...state_dict.pt
│   └── ...network_config.pickle
└── lan/
    └── ddm/
        ├── ...train_state_dict.pt
        └── ...network_config.pickle
```

The UI searches recursively, so both layouts are supported.

## Launch the UI

Start the app from the repository root:

```bash
uv run network-inspectors-ui
```

In the sidebar, set **Torch models base directory** to:

```text
data/torch_models
```

The **Model** selector should list both `angle` and `ddm`. Select a model, then use the `KDE vs LAN` or `3D Manifold` tab.

The default Streamlit project configuration hides the toolbar and Deploy button through `.streamlit/config.toml`.
